# Lab7B vs Lab8B — สรุปหน้าที่ + ประวัติแก้บั๊ก

อ้างอิงรายละเอียดทั้งหมดจาก `PROGRESS.md` (append-only, ไล่ตามหัวข้อ `## วันที่ — ...`)
ไฟล์นี้เป็นแค่สรุปสั้นสำหรับกลับมาดูเร็วๆ ว่าอะไรอยู่ Lab ไหน

## Lab7B (`src/ocr_system/lab7b_curriculum.py`) — OCR + VLM extraction

รูปหน้าเล่มหลักสูตร → ข้อมูลดิบ เป็นขั้นที่ "เดา/ตีความ" เยอะสุด เพราะพึ่งโมเดล 2 ตัวต่อกัน:

1. **Typhoon-OCR** (`scb10x/typhoon-ocr1.5-3b`) — รูป → Markdown (`intermediate_vlm.md`)
2. **VLM ข้อความ** (`qwen3:4b`) + `EXTRACT_PROMPT` — Markdown → JSON ตาม `COURSE_SCHEMA`
   (รหัสวิชา/ชื่อ/หน่วยกิต/ปี-ภาค ฯลฯ) → เอาต์พุต `pred_vlm.json`

ต้องรันออฟไลน์เท่านั้น (assert บังคับ `OLLAMA_HOST` เป็น localhost)

**ประวัติแก้บั๊ก (ทุกจุดคือจุดที่โมเดล "เดาผิด/ไม่นิ่ง" ไม่ใช่ deterministic bug):**
- **2026-09-10** ("สิ่งที่แก้") — เพิ่มกฎ `EXTRACT_PROMPT` ข้อ [2] (ห้ามเดา year=1 ให้หน้าที่ไม่มี
  "ปีที่ N ภาคที่ M") + ข้อ [7] (แยกชื่อไทย/อังกฤษที่ OCR รวมมาช่องเดียว) + เพิ่ม **deterministic
  post-filter** ใน `_text_to_json_chunked()` ล้าง year/semester เป็น null ถ้าก้อนนั้นไม่มีหัวข้อ
  ตารางแผนจริง (prompt อย่างเดียวเอาไม่อยู่)
- **2026-09-14** ("Lab 9: อาจารย์ขอให้ประเมินครบทุกเล่ม") — เจอบั๊ก **ตารางที่สองในหน้าเดียวกันหาย
  ทั้งยวง** (โมเดลหยุดเองหลังตารางแรก) แก้ด้วย `_split_page_into_table_chunks()` (ตัด chunk ที่ขอบ
  `<table>` จริง แทนตัดตามหน้าดิบ) — ยืนยันด้วย AIT ได้ครบ 13/13 วิชา (เดิม 6/13)
- **2026-09-15** ("รัน BIT no-coop") — เจอ **label หมวดวิชาปนเป็นชื่อวิชา** (เช่น
  "กลุ่มวิชาที่กำหนดโดยคณะ*" หลุดมาแทนชื่อจริง) แก้ `EXTRACT_PROMPT` ข้อ [6] เพิ่มกฎ+ตัวอย่างจริง
  เจาะจงเคสนี้

**ข้อจำกัดที่รู้แล้วแต่ยังแก้ไม่ได้ (ไม่ใช่ manual patch เพราะผู้ใช้สั่งห้าม):**
- OCR typo จุดเดียวที่โดนตราประทับ/วอเตอร์มาร์กทับพอดี (`06046409` ของ AIT, `96644042` ของ BIT
  no-coop) — ลองปรับ `LAB7B_MAX_IMAGE_DIM`, ลอง dewatermark ด้วย color-threshold แล้วไม่ได้ผล
  (รายละเอียดการทดลองอยู่ใน PROGRESS.md หัวข้อ 2026-09-15 "ทดลองแก้ typo ด้วยวิธี OCR ล้วน")
- `name_en` เป็น NULL บางรอบ — qwen3:4b บางทีไม่ยอม emit ชื่ออังกฤษ (2026-09-10)

## Lab8B (`src/ocr_system/lab8b_curriculum_db.py`) — แปลง DB + ตรวจ + ประเมิน

รับ `pred_vlm.json` จาก Lab7B มาทำงานต่อแบบ **deterministic ล้วนๆ ไม่เรียก LLM ซ้ำ** (ยกเว้นขั้น
`eval` ที่เรียก LLM แปลงคำถามเป็น SQL จริง):

| คำสั่ง | ทำอะไร |
|---|---|
| `import-lab7b` | `convert_lab7b()` — แปล schema Lab7B → Lab8B ด้วยกฎ regex/if-else ล้วน ได้ `curriculum.json` + `curriculum.conversion.json` (รายงาน warning) |
| `schema` / `load` | สร้าง schema + ยัดเข้า `curriculum.db` (SQLite) |
| `verify` | เช็คความสอดคล้องภายใน 7 ข้อ (CHK1-CHK7 เช่น หน่วยกิตรวม, รหัสวิชาซ้ำ, ลำดับ prerequisite) — ไม่พึ่งเฉลย |
| `eval` | ถาม-ตอบ NL→SQL จริงเทียบ `gold_questions.json` — แยก 2 ตัวเลขเสมอ: **SQL รันผ่าน** (เขียน SQL เป็นไหม) vs **ตอบถูก** (เข้าใจคำถามไหม) |

**ประวัติแก้บั๊ก:**
- **2026-09-10** ("สิ่งที่แก้" + "Lab8B: schema→import→load→verify→eval") — แก้ `convert_lab7b()`
  merge logic ให้ชื่อไทยจริงจากหน้าถัดไปแทนที่ชื่อที่หลุด (เป็นรหัส/อังกฤษล้วน) ได้ + แก้
  `SQL_PROMPT` (`ask()`) ให้ query ตาราง `prerequisite` เสมอสำหรับคำถามวิชาบังคับก่อน + ตอบ
  `SELECT NULL WHERE 0` เมื่อคำถามนอก schema (ค่าเทอม/อาจารย์) แทนการเดา → **ตอบถูกจาก 1/30 (3%)
  เป็น 30/30 (100%)**
- **2026-09-10** ("แก้บั๊กข้อความคำตอบ" + "ปรับ ANSWER_PROMPT") — บั๊กข้อความคำตอบ (SQL ถูกแต่ข้อความ
  ตอบผิด/echo คำถามกลับ) แก้ `ANSWER_PROMPT` 2 รอบจนได้ประโยคธรรมชาติโดยไม่พังเคสเดิม
- **2026-09-15** ("รัน BIT no-coop") — เจอ **cell OCR รวม rowspan 2 รหัสวิชาไว้ด้วยกัน**
  (`"06036146 96642033"`) `_lab7b_codes()` เดิม (regex `\d{8}` ล้วน ไม่เช็ค "หรือ") แตกเป็น 2 รหัส
  แล้วยัดชื่อ/หน่วยกิตแถวเดียวให้ทั้งคู่ ทำให้ชื่อที่ถูกของรหัสหนึ่งถูกทับเงียบๆ แก้เป็น
  `_ambiguous_code_merge()` ใหม่ + placeholder name เมื่อไม่แน่ใจ + แก้ `alt_group` ไม่ให้ปนกับ
  logic "A หรือ B" (ไม่งั้นนับหน่วยกิตหายไปครึ่งหนึ่งใน CHK1/CHK7) + เพิ่ม sanity-check warning
  ใหม่ใน `curriculum.conversion.json`

**ข้อจำกัดที่รู้แล้ว ไม่ใช่บั๊ก (structural, เอกสารเขียนแบบนั้นจริง):**
- CHK1/CHK7 มักไม่ผ่านเมื่อ input เป็นแค่บางส่วนของเล่ม หรือเล่มมีแถว "วิชาเลือก" ที่ใช้รหัส
  wildcard (เช่น `06026xxx`, `9664xxxx`) แทนรหัสจริง — `convert_lab7b()` ข้ามรหัส wildcard ออก
  ถูกต้องแล้ว (ไม่ใช่วิชาเจาะจง) ทำให้หน่วยกิตนับได้น้อยกว่าที่ประกาศจริง (ดู DSBA 2026-09-10,
  AIT/BIT 2026-09-14/15)
