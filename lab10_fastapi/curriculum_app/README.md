# Curriculum Application

แอปนี้รับคำถาม → ใช้ทางลัดจากข้อมูลหลักสูตร หรือให้ Qwen สร้าง SQL → อ่าน SQLite → ส่งกลับคำตอบ, SQL อ้างอิง และ rows

`sql` ของทางลัดเป็นคำค้นอ้างอิง ไม่ใช่ execution trace ทั้งหมด: อาจมีหลายคำค้น การกรอง/คำนวณใน Python หรือข้อมูลจากอีกแผน ส่วนคำถามที่ผ่าน Qwen ส่ง SQL ที่รันจริง ช่องนี้ใช้ตรวจแนวทางค้นข้อมูล ไม่ใช้ replay เพื่อรับรองผลเหมือนคำตอบทุกกรณี

ตรวจ UI จริงวันที่ 2026-10-05 บน production `636927e`, API ในเครื่อง port8002: Chrome headless โปรไฟล์ว่าง ผ่านฟอร์มถาม/วิชาบังคับก่อน/ผลกระทบถอน, idle/loading/success/error, ปิดปุ่มขณะรอ, เปลี่ยนแผนล้างผลเครื่องมือ, ทิ้ง response เก่าหลังเปลี่ยนแผน และจอ390pxไม่มีแนวนอนล้น ไม่พบ JavaScript exception; การทดสอบ response เก่าใช้ข้อมูล API จริงที่หน่วงการส่งกลับใน browser ไม่เพิ่ม dependency ระบบ ผลนี้ไม่ใช่การรับรอง deployment หรือคะแนน Challenge ของอาจารย์

### ขอบเขตผลกระทบการถอน

คำถาม เช่น `ถ้าถอนวิชา 90644007 ออกไป` ใช้ reverse prerequisite graph เดียวกับเครื่องมือตรวจผลกระทบ แสดงตัวต่อโดยตรง/ทางอ้อม พร้อมเงื่อนไขทางเลือกหรือเรียนร่วมกันและชื่อสองภาษา ไม่ต้องเรียก Qwen เพื่อเดาคู่ prerequisite; คำถามอื่นยังใช้ routing เดิม

แก้การสกัด prerequisite ที่ต้นฉบับระบุเป็นชื่อเต็มแทนรหัส เช่น FOUNDATION ENGLISH 1 โดยยอมรับเฉพาะชื่อที่ตรงและมีรหัสเดียว DSBA ทั้งสองแผนจึงมีคู่ `90644008 → requires 90644007` ตาม PDF209 (หน้าพิมพ์208) จำนวนคู่เพิ่มจาก5เป็น6; Gold v2.1 แก้จากต้นฉบับแล้ว และ v2.2 เพิ่มการแก้ AIT/IT พร้อมหลักฐานใน metadata

ช่องตรวจผลกระทบใช้หลักสูตร/แผนที่เลือกด้านบน รับรหัสวิชา 8 หลัก และอ่านความสัมพันธ์จาก SQLite โดยไม่ใช้ LLM หรือแก้ฐานข้อมูล ผลลัพธ์แยกตัวต่อโดยตรงและทางอ้อม พร้อมตัวอย่างเส้นทางสั้นที่สุด เงื่อนไขทางเลือก (`หรือ`) และเรียนร่วมกัน รวมถึงหน้า PDF ของคำอธิบายวิชาที่มีข้อมูลอ้างอิง

นี่คือรายวิชาที่อาจได้รับผลกระทบ หากถอนแล้วผู้ใช้ยังไม่เคยผ่านวิชาต้นทาง ไม่ใช่การยืนยันสิทธิ์ลงทะเบียนส่วนบุคคล เพราะยังไม่ได้รับประวัติวิชาที่ผ่านแล้ว วิชาทางเลือกที่ผ่าน และตารางลงทะเบียนของผู้ใช้ หากไม่พบเส้นทาง ระบบระบุว่าไม่พบความสัมพันธ์ในข้อมูล แทนการรับรองว่าไม่มีผลกระทบ

### ตัวอย่างคำถาม (`GET /api/sample-questions?program=<id>`)
หน้าเว็บแสดง 6 หัวข้อ (หน่วยกิต, ปี/เทอม, รายวิชา, บังคับก่อน, ถอนวิชา, เทียบแผน) หัวข้อละ 2-3 ข้อ endpoint นี้สร้างตัวอย่างจากข้อมูลของแผนที่เลือก: รูปแบบคำถามคงที่ ส่วนที่เว้นว่างเติมด้วยวิชาจริงของแผนนั้น (เช่น วิชาที่มีวิชาบังคับก่อนจริง วิชาที่มีวิชาอื่นต้องผ่านก่อนมากที่สุด) และมีเฉพาะข้อที่แผนนั้นตอบได้ — ไม่มีแผนคู่สหกิจ/ไม่สหกิจ (AIT) = ไม่มีหัวข้อเทียบแผน, ไม่มีช่องวิชาเลือกเสรี = ไม่มีข้อวิชาเลือกเสรี, ไม่มีโครงสร้างหมวดศึกษาทั่วไป = ใช้ข้อ "หน่วยกิตแต่ละหมวด" แทน; หัวข้อที่เหลือน้อยกว่า 2 ข้อไม่ถูกส่งมา
* **ผลลัพธ์**: `{"topics": [{"key", "examples": [{"label_th", "label_en", "th", "en", "needs_model"}]}]}`; `en` เป็นประโยคอังกฤษที่ `english_questions` แปลงได้; `needs_model: true` = คำตอบใช้โมเดลภาษา (ช้ากว่าเล็กน้อย)
* **ข้อผิดพลาด**: `404` ถ้าไม่รู้จักแผน, `503` ถ้าไม่มีไฟล์ฐานข้อมูล; หน้าเว็บใช้รายการสำรองในไฟล์ถ้าเรียกไม่ได้
* **รับประกันด้วยเทสต์**: ทุกข้อของทั้ง 7 แผน ตอบจากข้อมูลได้ทั้งภาษาไทยและอังกฤษ (ไม่ใช่ "ไม่พบข้อมูลนี้ในเล่มหลักสูตร")

### การค้นหารายวิชา (`GET /api/courses?search=...`)
* **ไม่ส่ง `search`**: คืนรายวิชาที่อยู่ในแผนการเรียน (ตาราง `course`) เรียงตามรหัส เหมือนเดิม ทุกแถวมี `source: "plan"`
* **ส่ง `search`**: ค้นทุกตารางที่มีชื่อวิชาในฐานข้อมูลแผนนั้น แล้วรวมตามรหัสวิชา: `course` (`source: "plan"`), `elective_group_course` (`"elective"` วิชาเลือก/ศึกษาทั่วไป) และ `course_description` (`"catalog"` มีในเล่มแต่ไม่อยู่ในแผน/กลุ่มเลือก)
* **กติกาการจับคู่** (ไม่สนตัวพิมพ์): ทุกคำในคำค้นต้องตรง (เรียงอย่างไรก็ได้) และไม่ต้องตรงช่องว่าง เช่น `ฐานข้อมูล ขั้นสูง` เจอ `ฐานข้อมูลขั้นสูง`, `machinelearning` เจอ `MACHINE LEARNING`; คำละตินสั้น (ไม่เกิน 3 ตัวอักษร เช่น `OS`, `AI`) ตรงทั้งคำเท่านั้น ไม่ตรงกลางคำ (`OS` ไม่เจอ `NOSQL`); ตัวย่อขยายด้วย `ACRONYM_MAP` ของตัวช่วยตอบคำถาม + `DB`, `AI`; ตัวเลขสั้นตรงกับตัวเลขในชื่อ (`calc 1` เจอ CALCULUS 1 ไม่เจอ CALCULUS 2) ส่วนเลขยาวตั้งแต่ 4 หลักตรงกับรหัสวิชา
* **ลำดับผล**: รหัสตรงเป๊ะ, รหัสขึ้นต้น, ชื่อขึ้นต้นด้วยคำค้น, ชื่อมีคำค้น, แล้วจึงเจอเฉพาะในคำอธิบายวิชา; เสมอกันเรียง plan, elective, catalog แล้วตามรหัส
* **ฟิลด์**: `code`, `name_th`, `name_en`, `credits` (ว่างได้เมื่อไม่มีในตาราง), ชั่วโมง, `description_th` และ `source`; วิชานอกแผนไม่มีชั่วโมง/คำอธิบายถ้าตารางที่พบไม่มี

### คำถามภาษาอังกฤษ (`POST /api/ask`)
ทางลัดของ Lab 8B จับประโยคภาษาไทย คำถามอังกฤษจึงเคยตกไปที่โมเดลและตอบต่างจากประโยคไทยเดียวกัน (เช่น "any database courses?" ได้ Calculus 2, คำถามถอนวิชาและเปรียบเทียบแผนสหกิจได้ "ไม่พบข้อมูล") ตอนนี้ `english_questions.py` แปลงประโยคอังกฤษที่รู้จักเป็นประโยคไทยที่ทางลัดตอบได้อยู่แล้วก่อนถาม จึงได้คำตอบเดียวกัน และ `question` ในผลลัพธ์ยังเป็นข้อความเดิมของผู้ใช้
* รองรับ: หน่วยกิตรวม/รายเทอม/รายปี/รายหมวด, วิชาในปีและเทอม (พร้อมหน่วยกิต), วิชาเลือกและวิชาเลือกเสรี, วิชาตามหัวข้อ (เช่น database, networks, machine learning), วิชาบังคับก่อน, วิชาที่ต้องผ่านวิชาหนึ่งก่อน, วิชาต่อ, ถอนวิชา, เปรียบเทียบแผนสหกิจ, หน่วยกิต/ปีเทอม/ชื่อของวิชาหนึ่ง (รหัสหรือชื่อ)
* ประโยคที่ไม่รู้จักและประโยคที่มีตัวอักษรไทยปนอยู่ไปทางเดิมทั้งหมด; "what is the course code of ..." ยังใช้ตัวจัดการภาษาอังกฤษเดิมของ Lab 8B
* หัวข้อที่อยู่ในตาราง `_TOPICS` แปลเป็นคำไทยในชื่อวิชา (database = ฐานข้อมูล); หัวข้ออื่นคงตามที่พิมพ์

### การใช้งาน API ตรวจสอบวิชาบังคับก่อน (`GET /api/courses/{code}/prerequisites`)
* **Path Parameter**: `code` รหัสวิชา 8 หลัก (เช่น `06016407`)
* **ผลลัพธ์**: คืน JSON ระบุวิชาที่ต้องผ่านก่อน (`prerequisites_required`), `prerequisite_status` และวิชาที่มีความสัมพันธ์ต่อ (`unlocked_courses`); ไม่ใช่การรับรองสิทธิ์ลงทะเบียนส่วนบุคคล
* **ตัวอย่างการเรียก**:
  ```bash
  curl -s http://127.0.0.1:8000/api/courses/06016407/prerequisites
  ```
* **วิชานอกแผน**: รหัสที่พบเฉพาะในตารางวิชาเลือกหรือคำอธิบายวิชา (ไม่อยู่ใน `course`) คืน 200 พร้อม `prerequisite_status: "not_in_plan"` และรายการว่าง (ระบบไม่มีข้อมูลบังคับก่อนของวิชานั้น); `withdrawal-impact` คืน 200 และตัวต่อว่างเช่นกัน; รหัสที่ไม่มีในฐานข้อมูลแผนนั้นเลยยังเป็น 404
* **หมายเหตุ**: รองรับ 7 แผน ส่ง `?program=<id>` จาก `/api/programs` เพื่อเลือกแผน; default เป็น DSBA สหกิจเมื่อไม่ได้ปรับ config จำนวนวิชาและความสัมพันธ์อ่านจากฐานข้อมูลแผนที่เลือก
