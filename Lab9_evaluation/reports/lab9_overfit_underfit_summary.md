### Underfit (พลาดแบบเดิมสม่ำเสมอ) — สถานะเทียบตารางหัวข้อ 2 ด้านล่าง

| ข้อจำกัดเดิม | สถานะ 2026-09-26 |
|---|---|
| วิชา wildcard ไม่ถูกนับหน่วยกิต | **แก้แล้ว** — นับผ่าน `plan_slot` (CHK1F) ตรงเล่มครบ 7 แผน |
| IT "เลือก 1 จาก 3 แทร็ก" นับเป็นบังคับทุกแทร็ก | **แก้แล้ว** — หัวกลุ่มที่ไม่มีรหัส ("กลุ่มวิชาด้าน...") = กลุ่มเลือก 1 |
| OCR รวมเซลล์/แถวผิด | **แก้บางส่วน** — `fill_missing_rows` (เติมแถวที่ qwen ตก) + `code_from_book` (กู้รหัสจาก OCR ทั้งเล่ม, แยกรหัสที่รวมกัน) |
| คู่ "หรือ" | ชื่อสลับกันแก้แล้ว (`or_course_names.py`); การนับตกและเกินพร้อมกันในเฉลยยังเป็นเรื่องวิธีวัด |
| IT coop คะแนนต่ำสม่ำเสมอ | ดีขึ้น (23 → 25/30, F1 0.889) แต่ยังต่ำสุดกลุ่ม: วิชาเกิน 2, ชั่วโมงปฏิบัติสูงสุด 36 (ควร 9), prerequisite 7 คู่ (ควร 8) |

**ที่ยังพลาดเหมือนเดิมทุกรอบ (underfit ที่เหลือ):** AIT `90641008` (0 หน่วยกิต) ถูกตราน้ำบังจน OCR อ่านไม่ได้ — แถวเดียวนี้ทำให้ AIT ตก 7 จาก 8 ข้อที่ผิด (จำนวนวิชาปี 1/1,
รหัสในปี 1/1, ชื่อวิชา, วิชา 0 หน่วยกิต, หน่วยกิตต่ำสุด, จำนวนวิชาทั้งหมด, จำนวนวิชาไม่มีชั่วโมงปฏิบัติ);
BIT ไม่มีวิชา 0 หน่วยกิตใน `course` (ตกข้อหน่วยกิตต่ำสุด + นับวิชาไม่มีชั่วโมงปฏิบัติ); ชื่อวิชาบางตัวสะกดผิดจาก OCR
(เช่น IT `การประมวลผลทางกายภาพ`) — ทั้งหมดเป็นข้อมูลที่ขั้นอ่านเล่มทำหาย ไม่ใช่ขั้นตอบคำถาม

### Overfit แบบ "ปรับตามข้อสอบเดิม" — ความเสี่ยงสูงขึ้น ต้องบอกตรง ๆ

- รอบนี้เพิ่มกฎอีกหลายข้อ (กู้รหัส/แถว, แก้ SQL, อ้างอิงหน้า) โดยดูผลของเล่ม 4 เล่มเดิม ตัวเลขทั้งหมดจึงยังเป็น **in-sample**
- สิ่งที่ลดความเสี่ยง: กฎไม่มีรหัสวิชา/เงื่อนไขเฉพาะหลักสูตร (เทสใช้ข้อมูลสังเคราะห์), เฉลยใช้วัดผลอย่างเดียว ไม่ถูกอ่านโดยโค้ดที่สร้างผล,
  ทุกกฎ dry-run ครบ 7 แผนก่อนใช้ และตรวจว่าแผนอื่นไม่ถดถอย
- สิ่งที่ยังขาด: **เล่มหลักสูตรที่ไม่เคยเห็น (held-out)** — ไม่มีตัวเลขใดในรายงานบอกได้ว่ากับเล่มใหม่จะได้เท่าไร
- อ้างอิงหน้า: ระดับ 1 อ้างถูก 84/88, ระดับ 2 28/37 — ตัววัดระดับ 2 ต่ำกว่าจริงเพราะหน้าที่คาดของ IT no-coop ชี้หน้าแผนสหกิจ
  (รายละเอียดใน `lab9_metrics_latest.md`)

## 0. ก่อนอ่าน: ระบบนี้ไม่ได้เทรนโมเดลเอง

ระบบใช้โมเดลสำเร็จรูป (Typhoon-OCR อ่านภาพ, qwen3:4b จัด JSON/ตอบ SQL) ร่วมกับ prompt และโค้ดของเราเอง จึงไม่มี train/validation loss

## 2. สัญญาณ underfit (ระบบพลาดแบบเดิมสม่ำเสมอ)

จุดที่พลาดเหมือนเดิมทุกรอบ ไม่ว่ารันซ้ำกี่ครั้ง แปลว่าเป็นข้อจำกัดของ schema/วิธีแปลง ไม่ใช่ความสุ่ม

| ข้อจำกัด | หลักฐาน |
|---|---|
| **วิชา wildcard / วิชาเลือกที่ไม่ระบุรหัส** (`9064xxxx`, `06026xxx`, `xxxxxxxx`) — schema เก็บรหัสจริงเท่านั้น | verify CHK1 (หน่วยกิตรวม) หรือ CHK7 (หน่วยกิตต่อภาค) ตกในทุกแผน; ผ่านสูงสุด 6/7 |
| **IT: "เลือก 1 จาก 3 แทร็ก"** ระบบดึงครบทุกแทร็กเป็นวิชาบังคับ ทำให้หน่วยกิตต่อภาคเกิน | IT ทั้งสองแผนตก CHK7 ทุกรอบ; หน่วยกิตรวม IT coop = 135 > 129 ที่ควรเป็น |
| **OCR รวมเซลล์/แถวผิด (rowspan)** เช่น IT `90642033` + `90644042` เป็นสองแถวบนหน้าแต่ OCR ใส่ `rowspan=2`; BIT no-coop `06036146` + `96642033` | ตรวจกับภาพหน้าจริงแล้ว (ดูหัวข้อ "ตรวจ scope ของ ground truth" ใน `lab7b_prf1_cerwer_2026-09-16.md`) |
| **คู่ "หรือ"** (สหกิจ/สหกิจต่างประเทศ) GT เก็บเป็นค่าเดียว ระบบแยกเป็นสองรหัส | AIT `06046443/44`, BIT coop `06036147/48`, IT coop `06016481/82` ถูกนับทั้ง "ตก" และ "เกิน" |
| **ไม่สกัดชื่ออังกฤษและวิชาบังคับก่อนโดยออกแบบ** | `name_en exact = 0.000` ทุก run (qwen3:4b ไม่ emit ชื่ออังกฤษ) |
| **IT coop คะแนนต่ำสม่ำเสมอ** | 23/30 ทั้งสองรอบ พลาดข้อสอบชุดเดียวกัน ไม่มีข้อไหนพลิก |

**ข้อสอบพลาดชุดเดียวกันทุกรอบ:** BIT coop พลาด 4 ข้อเดียวกันทั้งสองรอบ (นับวิชา 3 หน่วยกิต, วิชาปี 1 ภาค 1, วิชาที่ไม่มีชั่วโมงปฏิบัติการ,
หน่วยกิตต่ำสุด) — ตรวจแล้วมาจากข้อจำกัดข้างบน ไม่ใช่ความสุ่ม

## 3. ความเสี่ยง overfit แบบ "ปรับตามข้อสอบเดิม" — ยังไม่ได้ปิด

- ระหว่างงานเราแก้บั๊กใน pipeline 6 ข้อจากการดูผลของ 7 run และวัดซ้ำกับข้อสอบชุดเดิม แม้ทุกข้อเป็นการแก้ที่ใช้ร่วมกัน (ไม่ hack รายหลักสูตร)
  และตรวจ regression กับ run อื่นทุกครั้ง แต่ **ไม่มีข้อสอบ/เอกสารที่ไม่เคยเห็น (held-out)** มายืนยัน จึงยังไม่รู้ว่าคะแนน 25–29/30 จะเป็นเท่าไหร่กับหลักสูตรใหม่
- ข้อสอบ (gold questions) สร้างจาก ground truth อัตโนมัติ ไม่ได้เดาด้วยมือ แต่ GT เองมีข้อผิด: `06016401` (วิชาของ IT) อยู่ใน GT ของ AIT และ DSBA
  ทั้งที่ไม่มีในเอกสารเลย ทำให้นับเป็น "ตก" ทุกรอบโดยไม่ใช่ความผิดของระบบ (ที่มา ยืนยันไม่ได้ ควรถามเจ้าของ GT)
- ตัวเลข P/R/F1 ของ DSBA coop ต่ำ (P=0.538) ส่วนหนึ่งเพราะ input มีหน้าแคตตาล็อกวิชาเลือกนอกแผน (14 วิชาถูกนับเป็น "เกิน") ตัดออกแล้ว F1 จะเป็นประมาณ 0.737

## 4. ข้อจำกัดของหลักฐานชุดนี้

- รันซ้ำแค่ **1 รอบต่อแผน** (AIT มี 3 รอบ) ทั้งหมดบนเครื่องเดียวกัน ตั้งค่าเดียวกัน
- ไม่ใช่การทดสอบทางสถิติ: บอกได้ว่า "ในตัวอย่างนี้นิ่งหรือไม่นิ่ง" แต่บอกช่วงความแกว่งจริงไม่ได้
- ทุกแผนที่รันซ้ำเป็นแผนสหกิจ + ไม่สหกิจของ 4 หลักสูตรที่เรามี ไม่ได้ครอบคลุมเอกสารประเภทอื่น
- ผลการทดลองตัดหน้าเป็นแถบก่อน OCR (หน้า AIT_023: ทั้งหน้า 1280/1600 ตกสองรหัส, ตัด 4 แถบอ่านครบ) เป็นการทดลอง 1 หน้า 1 รอบ **ไม่ได้นำมาใช้ใน pipeline**

## 5. ข้อสรุป

1. **ความนิ่ง:** ระบบนิ่งในแผนที่ไม่มีตราน้ำทับแถว (BIT, IT) และนิ่งพอใช้ใน DSBA; **AIT ไม่นิ่ง** ด้วยสาเหตุที่ชี้ชัด (OCR + ตราน้ำ) — รายงานผล AIT เป็นช่วง ไม่ใช่รอบเดียว
2. **underfit:** มีข้อจำกัดเชิงโครงสร้างที่ทราบแล้ว (wildcard, เลือก 1 จาก 3 แทร็ก, รวมเซลล์ผิด, คู่ "หรือ") ทำให้คะแนนสูงสุดอยู่ราว 26–29/30 ไม่ถึง 30/30 อย่างสม่ำเสมอ
3. **overfit ตามข้อสอบเดิม:** ยังไม่ได้ทดสอบด้วยข้อมูลใหม่ — ระบุเป็นงานต่อไป
4. **งานต่อไป (ยังไม่ทำ):** (ก) held-out gold questions/เอกสารใหม่, (ข) ทดสอบ `temperature=0` ว่าลดความแกว่งได้ไหม,
   (ค) ตัดหน้าเป็นแถบก่อน OCR แล้ววัดซ้ำทั้ง 7 แผน (ต้องรันใหม่หลายชั่วโมงและตัวเลขทั้งหมดจะเปลี่ยน), (ง) แจ้งอาจารย์เรื่อง `06016401` ใน GT
